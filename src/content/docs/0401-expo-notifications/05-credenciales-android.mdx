Para que las notificaciones lleguen a dispositivos Android reales en producción (o Development Builds), necesitamos configurar un proyecto en **Firebase** y vincular sus credenciales con **EAS**.

### Mapa Conceptual

Así es como se conectan las piezas: Tu App, Firebase y los servidores de Expo (EAS).

<ZoomImage src={architectureImg} alt="Diagrama de flujo de credenciales Android (Firebase -> App / Cloud -> EAS)" />

:::caution[Requisito Previo]
Necesitas una cuenta de Google activa para acceder a Firebase Console y Google Cloud Platform.
:::

<StepHeader number="1" title="Nombre del Paquete (Package Name)" variant="pink" />

Igual que tú tienes un DNI o Cédula, tu App necesita un ID único en el mundo. Se llama **Package Name** y tiene formato de dominio inverso (ej: `com.tuempresa.tuapp`).

Configúralo en tu `app.json` bajo la sección de Android:

```json {4-5} title="app.json"
{
  "expo": {
    "android": {
      "package": "com.usuario.pushmaster",
      "googleServicesFile": "./google-services.json"
    }
  }
}
```

:::tip[Personalización]
Cambia `usuario` por tu nombre o marca. Este ID será permanente una vez subas la app a la Play Store.
:::

<StepHeader number="2" title="Configuración en Firebase Console" variant="orange" />

<Steps>

1.  Ve a la [Consola de Firebase](https://console.firebase.google.com/) y crea un nuevo proyecto (ej. "PushMaster").
    
    <ZoomImage src={createProjectImg} alt="Crear Nuevo Proyecto en Firebase Console" />

2.  En la vista general, añade una nueva aplicación **Android** (icono del robot <i class="fab fa-android"></i>).
3.  **Importante:** Usa **EXACTAMENTE** el mismo `package` que definiste en el paso anterior (ej. `com.usuario.pushmaster`).
    
    <ZoomImage src={registerAppImg} alt="Registrar App Android con Package Name" />

4.  Descarga el archivo `google-services.json` cuando te lo ofrezca.
5.  Coloca este archivo en la raíz de tu proyecto Expo.

</Steps>

```bash
📂 /
├──  src/
│   ├── 📱 app/
│   └── 🧱 components/
├── ⚙️ app.json
├── 🤖 google-services.json          <--- ¡Aquí! 
├── 🔧 babel.config.js
├── 📦 package.json
└── 📘 tsconfig.json
```

<Card title="⚠️ Seguridad en Repositorios" icon="warning">
  Si tu repositorio es público, **NO SUBAS** este archivo. Agrégalo a tu `.gitignore`.
  
  Aunque contiene identificadores públicos, es una buena práctica de higiene mantenerlo fuera del control de versiones si es posible, o usar secretos de EAS si trabajas en equipo.
</Card>

<StepHeader number="3" title="Subir Credenciales a EAS" variant="cyan" />

EAS necesita permiso para enviar notificaciones en tu nombre a través de los servidores de Google (FCM V1).

Ejecuta el siguiente comando en tu terminal:

```bash
eas credentials
```

Sigue el asistente interactivo:

<Steps>

1.  Selecciona **Android**.
2.  Selecciona **production** (generalmente las credenciales de push se comparten, pero production es lo estándar).
3.  Elige **Google Service Account Key** (para FCM V1).
    
    <ZoomImage src={easCliImg} alt="Menú CLI: EAS Credentials" />

    :::note[Diferencia Clave]
    Esto es diferente al `google-services.json`. El JSON anterior era para tu **App** (Cliente). Esta llave es para el **Servidor** de Expo (EAS).
    :::

4.  Si te pide generar una nueva (o subir una existente):
    *   Ve a la consola de Firebase -> Configuración del Proyecto -> **Cuentas de servicio**.
    *   Dale a "Generar nueva clave privada".
    
    <ZoomImage src={serviceAccountImg} alt="Generar Service Account Key en Firebase" />

    *   Sube ese archivo JSON al CLI de EAS cuando te lo pida.

</Steps>
